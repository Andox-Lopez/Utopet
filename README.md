# Utopet 桌宠 / Utopet Desktop Pet

> **1.0.3 起本程序更名为 Utopet**（原名 Shimeji 重制版）。安装新版时旧版会被
> 自动卸载，**设置与你自己添加的角色会完整保留**。
> Renamed from Shimeji to Utopet in 1.0.3.  Installing over the old build removes
> it but keeps your settings and any characters you added.

用 **Python + PySide6** 重新实现的桌面宠物引擎。
**100% 兼容原版 Group-Finity Shimeji 的 `Actions.xml` / `Behavior.xml` 配置。**

A desktop-mascot engine re-implemented in **Python + PySide6**,
**100% compatible with the original Group-Finity Shimeji configuration files**.

## 快速开始 / Quick Start

### 免安装版（推荐）/ Standalone build (recommended)

```cmd
python tools\build_release.py
:: 就运行这个 / run THIS one:
:: dist\Utopet\Utopet.exe
```

打包成**自包含可执行文件**：双击即运行，**不需要装 Python，也不需要 pip install**。
整个 `dist\Utopet\` 文件夹拷给谁都能跑（117 MB，含 Qt 运行库）。
角色包放在 exe 旁边的 `characters\`，用户自己丢角色进去就能被识别。

> ⚠️ **只运行 `dist\Utopet\Utopet.exe`**。构建脚本会在打包结束后自动删掉
> `build\` 目录——那里也曾躺着一个同名的 `Utopet.exe`，但它旁边的 `_internal`
> 是空的，双击只会报 `Failed to load Python DLL`。看到这种报错就是点错了。
>
> **Only run `dist\Utopet\Utopet.exe`.** The build script deletes `build\`
> afterwards precisely because a same-named `Utopet.exe` used to sit there
> with an empty `_internal` next to it; double-clicking *that* one yields
> "Failed to load Python DLL".

The build produces a **self-contained executable** — double-click it and it
runs, **no Python and no pip install required**.  Copy the whole
`dist\Utopet\` folder to anyone and it works (117 MB incl. the Qt runtime).
Character packs live in `characters\` next to the exe, so users can drop in
their own.

### 安装包 / Installer

```cmd
:: 1) 先构建自包含程序 / first build the standalone program
python tools\build_release.py
:: 2) 再生成安装包（characters 只打包 Miku）/ then build the installer
"C:\Program Files (x86)\Inno Setup 6\ISCC.exe" installer\Utopet.iss
:: 产物 / output:
output\Utopet-Setup-1.0.6.exe
```

Inno Setup 6 编译出 **34 MB** 的安装包（免安装版是 117 MB，LZMA2 压掉了约 70%），
默认装到 `C:\Program Files\Utopet\`，装完在开始菜单和桌面留快捷方式。

**安装向导是中文的** —— Inno 官方只带 29 个语言、**不含简体中文**，所以
`installer/ChineseSimplified.isl` 是本项目自己翻译的（281 条向导文案 + 12 条自定义
文案，零缺失）。它由 `tools/make_isl.py` 从 `compiler:Default.isl` 生成，
改译文后重跑该脚本即可，不会出现缺键。
The wizard is localised into Simplified Chinese. Inno Setup ships 29 languages
but **no Chinese** one, so `installer/ChineseSimplified.isl` is generated by
`tools/make_isl.py` from `compiler:Default.isl` — edit the table there and re-run.

安装包**只带 Miku 一个角色**（46 张图，1.1 MB）。用户把别的角色包丢进安装目录的
`characters\` 就能被识别；卸载时 `characters\` 目录会被保留（除非里面是空的）。
向导提供「安装给所有用户 / 只安装给我自己」两种模式；**装完不会自动启动**桌宠
（桌宠会弹任务栏面板，容易打断人），只在结束时问一次要不要启动。

> ⚠️ 重新打包前记得先从托盘**退出正在运行的桌宠**，否则 exe 被占用会导致构建失败。

### 源码运行 / From source

```cmd
双击 启动桌宠.bat
:: 或者 / or
python main.py
```

依赖 / Requirements: `Python 3.11+`, `pip install -r requirements.txt` (PySide6)

> 启动器会自动挑选**确实装了 PySide6** 的那个解释器 —— Windows 上
> `where python` 常返回好几个候选，PATH 里排前面的那个往往没装依赖，
> 这正是以前「双击后弹 ModuleNotFoundError」的真正原因。
> The launcher probes each candidate interpreter for a working PySide6
> instead of blindly taking the first one on PATH.

启动后：任务栏出现**常驻控制面板**（可右键「固定到任务栏」），系统托盘出现 Logo
图标；**右键宠物本体**、托盘图标或面板按钮都可以操作。托盘右键和宠物右键是
**同一份菜单**，在哪点都一样。想要一群？面板第一行是 `[数量] [召唤]`，
把数字调成 5 再点「召唤」，或托盘菜单 →「一次召唤多只…」。
关掉面板它只是藏起来，**程序仍在托盘常驻**，右键托盘图标选「显示任务栏面板」
就能叫回来。

On start: an **always-on taskbar panel** appears (right-click it to "Pin to
taskbar"), a logo tray icon shows up as well; **right-click the mascot**, the
tray icon or use the panel buttons.  The tray and the mascot share **one single
menu**, so right-clicking either gives the same items.  Want a crowd?  The panel's
first row is `[count] [Summon]` — set the number to 5 and press Summon, or use
Tray menu → "Summon several…".  Closing the panel only hides it; the app stays
resident **in the tray**, and Tray menu → "Show taskbar panel" brings it back.

## 配置兼容性 / Configuration compatibility

`characters/<角色>/conf/` 下的 `Actions.xml` 与 `Behavior.xml` 与原版完全同构，
可以直接把任何原版角色包丢进 `characters\`。

The files under `characters/<name>/conf/` are schema-identical to the original,
so any original character pack can be dropped into `characters\`.

标签写法 / tag spellings accepted:

```xml
<!-- 原版日文 / original Japanese -->
<動作 名前="歩く" 種類="移動" 枠="地面"> ...
<!-- 中文 / Chinese -->
<动作 名称="走路" 类型="移动" 框="地面"> ...
<!-- 英文 / English -->
<action name="Walk" kind="move" frame="ground"> ...
```

## 反编译校准的关键语义 / Semantics recovered from the decompiled jar

| 项目 | 结论 |
| --- | --- |
| `Pose.next` | `anchor.x += lookRight ? -dx : dx`，图片朝右时镜像 |
| `Look.apply` | `右向き` 缺省 = `!lookRight`，即**直接翻转朝向** |
| `Move.tick` | 每帧 `setLookRight(anchor.x < 目的地X)`，始终面朝目标 |
| `Jump.tick` | 非抛物线，是朝目标点的**匀速直线冲刺** |
| `Fall.tick` | `v -= v*空気抵抗`，`vy += 重力`，小数部分累积进位 |
| `Border.isOn` | `±2px` 边界容差，`±10px` 沿边范围 |
| `Environment.floor` | 优先宠物脚下窗口的顶边，否则工作区下边 |
| 动作帧率 | 40 ms/帧（25 fps） |

## 已知限制 / Known limitations

- 「マウスの周りに集まる」的后续行为列表在原版配置里是封闭的，进入后宠物会一直
  坐着看鼠标，因此**鼠标空闲聚集默认关闭**，可在 设置 → 行为 里打开。
  The "gather around cursor" chain is self-contained in the original
  configuration, so idle-gather is **off by default** (Settings → Behaviour).
- 窗口交互（扛/扔窗口）对最大化的窗口自动跳过。
  Window interaction is skipped for maximised windows.
- 会话恢复续播**只对同一个行为生效**：存档里的行为在当前角色的动作表里找不到时
  （比如换了角色，或那个动作被停用了），按正常随机挑，不会给别的动作白跳帧。
  Session-restore resume applies **only when the same behaviour is chosen**; if the
  saved behaviour is absent from the current character's table (character switched,
  action disabled) the normal random pick takes over instead of fast-forwarding an
  unrelated action.
- 补帧上限 20000 帧（25 fps 下约 13 分钟）—— 更长的循环动作不值得在启动时
  逐帧补回来。 Resumption is clamped at 20 000 frames (~13 min at 25 fps).
- 全局快捷键只能改 `config\settings.json`，设置界面里目前只显示改键方法，不做
  按键捕获。 Global hotkeys are edited in `config\settings.json`; the Settings
  dialog explains how but does not capture keystrokes.

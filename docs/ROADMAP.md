## 一、立刻可做（低风险、收益明确）

### 1. README 与实际行为不一致 ⭐ 优先

**问题**：README 第 73 行和第 156-158 行仍写着「窗口互动**只认前台窗口**」，
还让用户「要让它爬某个窗口，先把这个窗口点到前台」。

**但 1.1.2 已经改掉了这条规则** —— 现在是「光标 + 未被完全遮盖」（见 CHANGELOG
1.1.2）。文档与行为矛盾，访客照着做会以为程序有 bug。

**改动**：
- 功能表那行改成「光标所在、且没被完全遮盖的窗口」
- 限制段改写：说明「把鼠标移到那扇窗口上，宠物就会去爬它；被别的窗口完全盖住的
  窗口不参与互动（宠物在看不见的边上走会变成凭空位移）」
- 英文区同步（现在的英文区比中文区还少一条限制，两边不对等）

**验收**：`grep -n "只认前台\|点到前台" README.md` 无输出。

### 2. 发版脚本找不到 `gh` ⭐

**问题**：`gh` 装在 `C:/Program Files/GitHub CLI/gh.exe`，**不在默认 PATH**。
每次发版都要手工 `export PATH="$PATH:/c/Program Files/GitHub CLI"`。
上次发 1.1.2 时 PATH 里恰好有它，这次没有 —— 属于「看运气」。

**改动**：仿照现有的 `find_iscc()`，在 `tools/release.py` 里加一个 `find_gh()`，
按顺序找：
1. 环境变量 `GH` / `GITHUB_CLI`
2. `C:/Program Files/GitHub CLI/gh.exe`（含 `(x86)` 变体）
3. PATH 里的 `gh`

**验收**：把 PATH 清空后跑 `--dry-run`，仍能通过「gh 可用」的预检。

### 3. `analysis/` 的 gitignore 说明与实际不符 ✅ 已修正

**原判断（错的）**：`.gitignore` 里有 `analysis/*`，新写的测试脚本 `git add -A`
不会带上，得手动 `git add -f`。

**实测结论**：`.gitignore` 里**根本没有** `analysis/*` 这条规则 —— 只有
`analysis/_*` 和几个截图产物（`analysis/appearance_*.png` 等）。新建一个
`analysis/verify_x.py`，普通 `git add` 就能带上；42 个测试脚本一直都在版本
控制里。**是我记错了。**

**真正的问题在别处**：`tools/release.py` 里那段注释和警告把原因写成了
「整个 analysis 目录被忽略」，于是**每次发版都会有一条不存在的风险提示**，
而真正需要提醒的情况（某个 .py 被别的规则挡了）反而不显眼。

**改动**：
- `release.py` 的注释改成准确描述；**检查本身留着**（规则随时可能变，
  「测试没提交」是最容易漏掉又最难发现的坑）
- `.gitignore` 里给 `docs/ROADMAP.md` 加例外 —— `docs/*` 确实会忽略整个目录，
  新文件要 `git add -f` 才带得上，漏了等于这份清单只存在于某台机器上
- 顺带把 gh 自己写的 `.local/state/gh/device-id`（设备标识，本机状态）
  加进 `.gitignore`

### 5. 补测试盲区 ✅ 已完成 —— **过程中找出 3 个真 bug**

**现状**：25 个测试文件，326 项物理回归。但有 12 个模块**无直接测试**：

| 模块 | 风险 | 为什么重要 |
|---|---|---|
| `engine/mascot.py` | 高 | 镜像/位图缓存/朝向 —— **1.1.2 刚改过爬墙镜像**，却没测试守着 |
| `engine/brain.py` | 高 | 行为选择（权重/条件/next_list 链）—— 行为链断了很难查 |
| `xml/expr.py` | 高 | `Behavior.xml` 的条件全靠它求值 —— 表达式一坏，整套行为静默失效 |
| `gui/action_editor.py` | 中 | 用户可编辑动作 —— 改坏了会写坏角色包，且**没有校验** |
| `xml/config.py` | 中 | 解析器 —— 畸形 XML 的表现未知 |
| `gui/pomodoro_window.py` | 中 | GUI 那侧的状态同步 |
| `i18n.py` / `icons.py` / `names.py` | 低 | 补语言包键、图标回退 |
| `xml/aliases.py` | 低 | 日文别名映射 |

**实际顺序与结果**：`mascot.py`（镜像/朝向，24 项）→ `expr.py`（表达式求值，63 项）
→ `brain.py`（行为链，22 项）。

### ⭐⭐ 补测试的真正回报：找出 3 个**一直在静默失效**的真 bug

补测试本身是「防未来」，但这三个是「**现在就已经坏了**」：

| # | 模块 | Bug | 影响 |
|---|---|---|---|
| 1 | `xml/expr.py` | 三元运算符**被括号包住**时翻译失败 | 原版「壁から落ちる」行为**永远不会被选中**（Ayaka/Miku/花卷 全中） |
| 2 | `xml/expr.py` | `!` 译成 ` not `（带前导空格） | **9 处**以 `!` 开头的条件永远不成立 |
| 3 | `engine/brain.py` | 「有约束但候选全不满足」被当成「没有约束」 | `追加="false"` 名不副实，会选到约束外的行为 |

**共同点：症状都是「某条行为永远不生效」，而且完全静默** ——
`Expr.__init__` 里 `except SyntaxError: self.code = None` 把编译失败吞掉了。

⭐ **教训**：单元测试只能验证「我想到的写法」；**扫真实配置**才能发现真问题。
所以 `verify_expr.py` 有一节直接遍历所有角色包里的 **687 处表达式**。

**验收**：每个新模块的测试要能回答「它坏了会怎样」，而不是「它返回了什么」；
每组都要用**变异测试**验证鉴别力（故意改坏源码，确认断言会挂）。

### 6. 29 处裸 `except Exception` 逐个排查 ⭐ 项目自己的教训

**证据**：`grep -rn "except Exception" shimeji/` → **29 处**，
其中 15 处直接 `pass` 吞掉。

**项目笔记里的原话**：
> 裸 `except Exception` 是无声功能的最佳藏身处（`_reclaim_window` 的 TypeError
> 被吞了 7 个版本）。**看到裸 except 就去查它吞了什么。**

`_reclaim_window` 那个 bug 被吞了 **7 个版本**才被发现 —— 说明这类问题平均要漏好
几个版本。29 处里哪怕只有 3 处藏着真 bug，就是 21 个版本的静默故障。

**做法**：逐个打开看它吞的异常是什么，然后：
- 确实该吞的（存档读失败、单个宠物出错不影响其它）→ **加注释说明为什么**
- 不该吞的 → 修
- 拿不准的 → 加日志（`log.warning` 带上异常），让它**可观测**

**验收**：29 处每处都有注释或已修；`log.warning` 的路径能被测试捕获。

### 7. 三个既有 flaky 测试

**实测数据**（2026-10-23，20 次连跑）：

| 断言 | 旧代码 | 新代码 | 判定 |
|---|---|---|---|
| 爬墙逐帧推进 / 平滑 | 2/20 | 同量级 | 既有 flaky |
| 行为名对不上时不照搬存档帧数 | 低频 | 同量级 | 既有 flaky |
| 重启后恢复了 1 只宠物 | 2/20 | 3/20 | 既有 flaky |

**为什么值得修**：flaky 测试会**训练人忽略红灯**。团队里只要有一个人学会
「这个失败是已知的」，整个回归的可信度就没了 —— 而这个项目历史上正是靠
回归抓住了一串静默 bug。

**做法**：这类断言依赖随机数（`random.randint` 的跳帧）和真实计时。
要么把随机源**注入**（测试里 `random.seed()`），要么把断言改成统计性的
（「20 次里至少 15 次满足」）。

## 三、可以先观察（数据不够，暂不动）

### 8. 遮挡判定的性能

**实测**（`analysis/diag_perf.py`）：

```
真实桌面 9 扇窗     0.085 ms      ← 无压力
20 扇               0.568 ms
40 扇               2.708 ms
80 扇              10.868 ms      ← 帧预算 40ms 的 27%
```

复杂度 **O(n²)**（n 扇窗口 × n 个更高层窗口 × 9 个采样点）。真实场景完全够用，
但**窗口极多的用户**（40+ 扇互相重叠）会吃掉四分之一帧预算。

**判断**：**暂不优化**。这是「有数据但没有用户抱怨」的状态。等真有人报卡顿，
或者要做「窗口很多时的降级策略」时再动。

**若要动**：把 9 点采样改成**一次遍历的面积并集**算法（O(n)），
或者加「窗口数超阈值时降级为只查快速路径」。

**记录**：这个数字是排查「用户说卡」时的第一手线索，别重新测。

### 9. `manager.py` 2232 行

12 个模块超过 300 行，7 个超过 500 行。`manager.py` 最大。

**判断**：**先不拆**。这个项目历史上因为「搬页/大段改动」出过多次事故
（方法被插进 `__init__` 中间、`closeEvent` 位置搞错等）。而且
`manager.py` 大部分是**平铺的功能方法**（面板、菜单、番茄钟、设置），
拆成子模块的收益主要是「看着舒服」，不是「更好维护」。

**若要拆**，先写**方法清单 diff**（`re.findall(r"^    def (\w+)", src, re.M)`），
拆完对比 —— 静默 exit=0 不等于成功。
